# 工作协议详解

## 为什么要一套协议

智能体的行为主要由第一轮用户输入之前的系统提示决定。profile 里会堆技能、工具、MCP，
但很少有对这四个问题的**统一**回答：

1. 用户应该先看到什么？
2. 请求到什么程度算清楚、可以直接动手？
3. 什么时候必须停下来问？
4. 说“完成”之前必须成立什么？

`dsh-agent-protocol` 把这四个问题的答案写成一段系统提示，让同一 profile 下的每个智能体
在**第一轮**就表现一致，而不是等用户纠正三轮之后才对齐。

## 分段说明

### 0. 可见性

每条实质回复首行写精炼任务行（`【任务】` / `[Task]`，15–40 字）。本轮加载了技能就补
「技能」标记；需要先问就补「需确认：N 个问题」；直接开工但存在未知则单列一行【假设】，
而不是把猜测藏在正文里。

作用：长对话难以审计，一行意图让“这一轮到底干了什么”可回溯，也让悄悄扩大的范围暴露出来。

### 1. 一次精炼

把口语（“把文档弄好点”“修一下那个”）压成一句 15–40 字的任务陈述，含动作、对象、约束、
所用能力。**这句就是执行指令，禁止再写第二版**——重复改写是智能体最常见的浪费。

只有当压缩后仍存在影响结果的歧义时，才追加一次结构化说明（目标/输入/约束/步骤/验收/回退）。

### 1b. 严格模式

任一命中即触发：约束或要求 ≥3 条；跨 ≥3 个文件或 ≥2 个子系统；不可逆或高风险；
预计 >10 分钟或需多轮；用户明确要求严谨。

触发后三件事强制执行：

- **约束表**：每条约束配一条**可判定**的验收标准；
- 缺失项**开工前**确认，不许用【假设】糊过去；
- 交付时**逐条**回填自检（满足/未满足 + 证据），而不是笼统说“已完成”。

要注意**不强制**的事：反问。严格模式管的是产出形态；是否提问由第 3 段决定，
只有真实缺口存在时才问。信息完整的高要求任务会表现为“约束表 + 直接开工 + 逐条回填”，零提问。

### 2. 能力路由

技能与工具按**能力语义**匹配，而非字面关键词，命中先加载再执行，鼓励串联。回复前自检
有没有漏用能力；依赖不可用时必须说明并给降级方案，不许静默绕过。

### 3. 先问后做

七类触发，每条都具体到可核对：

1. 同一交付物有 ≥2 种合理解释；
2. 缺关键数值、范围或口径；
3. 使用模糊词（优化一下/搞一下/那个/看着办/差不多/随便）；
4. 不可逆操作且对象或影响面不明；
5. 返工成本超过一轮对话；
6. 用户明确要求先确认；
7. 判定为科研类任务（文献、仿真、实验设计、数据分析、论文选题、组会答辩）。

最多问 3 个，每个带选项和推荐默认值。**反向约束同样重要**：读文件、检索、检查环境
就能确认的一律不许问——`package.json` 里有的配置值不是问题，是一次读取。

### 4. 团队

团队成本高，只在 ≥4 步、可并行独立子任务、调研→实现→验证分工、长耗时或用户明确要求时启用。
成员简报必须含任务、技能、验收标准和产物路径。

### 5. 效率与安全

无开关、常驻：独立子任务并行；改删前备份或说明影响；大文件先检索再分段读；
中文优先、结论先行、多用表格、不贴无关日志。

### 6. 交付自检

说“完成”前过六问：技能声明=实际加载？验收满足？产物路径给出？覆盖/删除有回退？
该问的问了？结果是验证过而不是假设的？

## 一个完整例子

需求：*“把两个 locale 文件都改一遍，README 补上漏掉的配置，版本号升一下，然后发布。”*

- **严格模式？** 4 条要求（≥3）+ 4 个文件（≥3）+ `publish` 不可逆 → 三条同时命中。
- **要反问？** 一个问题：*“patch 还是 minor？补一条已实现的配置键属于功能，建议 minor。”*
  （属于“缺关键数值”，且会改变产物。）
- **约束表**：locale 均为合法 JSON / README 列全所有键 / 版本号与 npm 最新版可区分 /
  tarball 含 `lib`、`docs`、`icon.svg`。
- **交付**：四行逐条标“满足 + 证据”（文件行号、命令输出），并附回退说明
  （已发布版本 72 小时后无法撤回；本地备份路径已记录）。

如果一开始就没有缺口，同一任务会输出约束表、直接执行、交付时**零反问**。

## 常见问题

**是硬门禁吗？** 不是。它只是系统提示文本，模型仍可能偏离；插件不拦截工具调用、不校验产出。

**会让每轮都变慢吗？** 只有严格模式任务付出表格成本。单条事实问题只会多一行任务陈述。

**能只关某一段吗？** 能。九个开关，在“设置 → 插件”里改，无需重装。第 5 段没有开关。

**支持英文吗？** 支持，`language: en` 切换整段协议文本。

**会往 profile 写文件吗？** 不会。安装只新增一行 Host 配置，卸载即无残留。
