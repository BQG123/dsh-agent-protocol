# 工作协议详解

## 为什么要一套协议

智能体的行为主要由第一轮用户输入之前的系统提示决定。profile 里会堆技能、工具、MCP，
但很少有对这四个问题的**统一**回答：

1. 用户应该先看到什么？
2. 请求到什么程度算清楚、可以直接动手？
3. 什么时候必须停下来问？
4. 说“完成”之前必须成立什么？

`dsh-agent-protocol` 把这四个问题的答案写成一段系统提示，让同一 profile 下的每个智能体
在**第一轮**就表现一致，而不是等用户纠正三轮之后才对齐。

协议第一句话就声明优先级：与用户当前的明确指示冲突时，以用户指示为准。

## 分段说明

段落编号在生成时连续排列，下面按出现顺序说明。

### 可见性

开始一项**新任务**的第一条回复，首行写任务行（`【任务】` / `[Task]`，15–40 字）。
追问、同一任务的后续回复、寒暄和简短问答不写——任务行是给一项任务立的路标，不是每条回复的抬头。
加载技能时，在加载它的那条回复里单列一行【技能】，不回头改任务行。

带着未确认的前提开工时，单列一行【假设】，而不是把猜测藏在正文里。这一条没有开关：
“先问后做”的很多出口都落在【假设】上，它必须始终有定义。

### 一次精炼

把口语（“把文档弄好点”“修一下那个”）压成一句任务陈述，含动作、对象、约束、所用能力。
**这句就是执行指令，不再写第二版**——重复改写是智能体最常见的浪费。

只有当压缩后仍存在影响结果的歧义时，才追加一次结构化说明（目标/输入/约束/步骤/验收/回退）。

### 严格模式

任一命中即触发：明确的约束或要求 ≥3 条；跨 ≥2 个子系统或大范围改动（约 ≥5 个文件）；
不可逆或高风险；预计 >10 分钟或需多轮；用户明确要求严谨。

触发后：

- 开工前列**约束清单**，每条配一条**可判定**的验收标准；
- 缺失项先确认；
- 交付时**逐条**对照（满足/未满足 + 证据），而不是笼统说“已完成”。

未触发时明确要求**不要**输出约束清单，避免普通任务也被套上表格。
`preset: strict` 会把触发条件换成“所有非琐碎任务”。

严格模式管的是产出形态；是否提问由“先问后做”决定。信息完整的高要求任务会表现为
“约束清单 + 直接开工 + 逐条对照”，零提问。

### 能力路由

技能与工具按**能力语义**匹配，而非字面关键词，命中先加载再执行，鼓励串联。回复前自检
有没有漏用能力；依赖不可用时必须说明并给降级方案，不许静默绕过。

### 先问后做

这一段的目标是**问得少而准**。只有五类情况必须先问：

1. 交付物有 ≥2 种合理解释，且选错需要返工；
2. 缺关键数值、范围或口径；
3. 指代或要求模糊，且上下文、文件、历史都无法消解；
4. 不可逆操作且对象或影响面不明；
5. 用户明确要求先确认。

`researchClarify` 开启时（默认开）追加第六类：科研类任务（文献、仿真、实验设计、数据分析、
论文选题、组会答辩）开工前确认范围、口径与产出形式——用户已经给出的项不重复问。

怎么问：一次问完，最多 3 个，每个带选项并标出推荐项；宿主提供提问工具
（如 `ask_user_question`）时用工具问，用户点选即可。

**三类不许问**，这是减少打扰的关键：

- 读文件、检索、检查环境就能确认的——`package.json` 里有的配置值不是问题，是一次读取；
- 可逆且做错代价小的——按最合理的理解直接做，写一行【假设】；
- 用户已经说“直接做 / 你决定”的。

用户回答后直接执行，同一问题不重复问。

**无人可问时**：DSH 的系统提示在父子智能体之间保持一致，子智能体、后台任务、定时任务
都会收到这份协议，但它们面前没有用户。协议要求这种情况下不提问也不停下，按最合理的理解执行，
并在结果里列出【假设】交给上级判断。

### 团队

团队成本高，只在 ≥4 步且可拆出独立并行子任务、调研→实现→验证分工、长耗时或用户明确要求时启用。
成员简报必须含任务、技能、验收标准和产物路径。不向用户汇报团队字段——界面上能看到。

### 效率与安全

无开关、常驻：独立子任务并行；改删前备份或说明影响；不可逆操作先讲后果；大文件先检索再分段读；
用用户的语言回复、结论先行、适合对比或枚举时用表格、不贴无关日志。

### 交付自检

说“完成”前默念六问：技能声明=实际加载？验收满足？产物路径给出？覆盖/删除有回退？
该问的问了？结论是验证过而不是假设的？

自检**不必输出**，只有严格模式才输出逐条对照。相关段落被关闭时，对应的问题也会从清单里去掉。

### 附加规则

`extraRules` 里的每一项作为一条规则追加在最后一段，用来放部署自己的条款，不必 fork 插件。

## 设置页

侧栏的 **工作协议** 入口打开设置页，左侧是档位、开关、各段提示词和附加规则，右侧实时显示
最终注入的全文、字符数和估算 token 数。每一段的正文都可以改写，改写过的段落会标“已修改”，
并可一键恢复默认；改写后的段落不再随开关变化措辞。保存后所有会话从下一次模型请求起生效，
不用重启。页面上的修改叠加在“设置 → 插件”的行配置之上，存放在
`$DSH_HOME/agent-protocol/overrides.json`。

## 档位怎么选

| 档位 | 适合 | 表现 |
|---|---|---|
| `lite` | 觉得协议打扰多、以日常对话和小改动为主 | 没有任务行、没有约束清单、没有自检要求；只保留精炼、能力路由和先问后做 |
| `standard` | 默认 | 新任务一行任务行；复杂任务才进严格模式 |
| `strict` | 发布、迁移、科研交付等不容出错的场景 | 所有非琐碎任务都列约束清单并逐条对照 |

档位只决定开关的默认值，显式写出的开关永远优先。

## 一个完整例子

需求：*“把两个 locale 文件都改一遍，README 补上漏掉的配置，版本号升一下，然后发布。”*

- **严格模式？** 4 条要求（≥3）+ `publish` 不可逆 → 两条同时命中。
- **要反问？** 一个问题：*“patch 还是 minor？补一条已实现的配置键属于功能，建议 minor。”*
  （属于“缺关键数值”，且会改变产物。）
- **约束清单**：locale 均为合法 JSON / README 列全所有键 / 版本号与 npm 最新版可区分 /
  tarball 含 `lib`、`docs`、`icon.svg`。
- **交付**：四行逐条标“满足 + 证据”（文件行号、命令输出），并附回退说明
  （已发布版本 72 小时后无法撤回；本地备份路径已记录）。

如果一开始就没有缺口，同一任务会输出约束清单、直接执行、交付时**零反问**。

反过来，需求是 *“把这个函数名改得好懂一点”*：可逆、代价小 → 不问，直接改，
写一行“【假设】按调用方语义命名为 …”。

## 常见问题

**是硬门禁吗？** 不是。它只是系统提示文本，模型仍可能偏离；插件不拦截工具调用、不校验产出。

**会让每轮都变慢吗？** 不会。任务行只在新任务的第一条回复出现；只有严格模式任务付出清单成本；
自检默认不输出。

**还是觉得问得多？** 关掉 `researchClarify`，或直接用 `preset: lite`。也可以在对话里说
“直接做”，协议规定此后不再问。

**能只关某一段吗？** 能。八个开关加三个档位，在侧栏的“工作协议”页里改，保存即生效。
“效率与安全”和【假设】行没有开关。

**支持英文吗？** 支持，`language: en` 切换整段协议文本。回复语言始终跟随用户，与此设置无关。

**会往 profile 写文件吗？** 不会。安装只新增一行 Host 配置；在设置页保存时会写
`$DSH_HOME/agent-protocol/overrides.json` 这一个文件，卸载后可手动删除。

## 兼容性

`engines.dsh`：`>=0.2.2-rc.1 <0.3.0-0`。不联网、无遥测、不采集数据。
